# Boxelder: Factorio 2.0 mod

A joke mod for Minnesotans: small biters become **boxelder bugs**, medium biters
become **Asian beetles**. It is an **art replacement only**. `data.lua` swaps
sprites and icons on the existing `small-biter` / `medium-biter` prototypes and
their corpses. Health, speed, AI, spawning and stats stay vanilla, and the mod has
no `control.lua`. Jon was explicit about this, so don't add behaviour.

Researched against Factorio **2.0.77** with Space Age (Steam, macOS).
API docs: `npx ctx7@latest docs /websites/lua-api_factorio_stable "<topic>"`. For
how vanilla does something, the game's own Lua (paths below) is the better
reference: the docs leave out sheet layout and blend details.

## Layout

```
data.lua                 the whole mod: points 8 animations + 4 icons at graphics/
info.json, locale/
art/<target>/            SOURCE ART, hand-edited. One PNG per frame. Git LFS.
  manifest.json          canvas size + shift per animation; pack-art.py reads it
  <anim>/color/NN-DIR/FF.png, <anim>/shadow/NN-DIR/FF.png
  previews/<anim>.png    contact sheets (rows = directions); generated, not read back
  icons/
graphics/                GENERATED by tools/pack-art.py and gitignored. Never edit.
scenarios/lab/           test scenario + /boxelder-spawn, /boxelder-kill (dev only)
tools/
  extract-biter-art.py   vanilla sheets -> art/ (one-off; already run)
  pack-art.py            art/ -> graphics/ sheets + .lua metadata
  lab.sh                 pack, then launch Factorio straight into the lab
  check.sh               headless validation in a throwaway profile
```

Targets: `boxelder-bug` → `small-biter` (scale 0.5); `asian-beetle` →
`medium-biter` (scale 0.7).

## Workflow

1. Edit frames in `art/<target>/<anim>/color/` (and `shadow/` if the outline changes).
2. `tools/lab.sh` packs and opens the lab. Factorio must be closed first: sprites
   load only at startup, and `open` passes no arguments to a running instance.
3. `tools/check.sh` after any change to `data.lua`, the packer or the scenario.

Python tools are PEP 723 scripts: run them with `uv run tools/<name>.py`. uv
resolves numpy/pillow per run, so nothing goes into a global pip.

**Never re-run `extract-biter-art.py --force`** once art has been edited. It deletes
`art/<target>/` and re-extracts vanilla. Without `--force` it refuses to run.

## Frame contract (what the art must keep)

- **Canvas size is fixed per animation**, e.g. run 398x313, attack 360x348,
  die 490x384, decay 534x402; shadows differ (see `manifest.json`). The frame
  centre is the anchor in game, so resizing or cropping slides the sprite away
  from its shadow and hitbox. `pack-art.py` rejects wrong sizes and missing frames
  before writing anything.
- **Transparent background.** The packer warns on any frame with no transparent
  pixels: an editor that flattened the image.
- **16 directions**, folder `00-N` faces north, then clockwise (`04-E`, `08-S`,
  `12-W`). Frames per direction: run 16, attack 11, die 17, decay 24.
- Sheets are drawn at `scale * 0.5`, so a small biter shows at ~25% of the frame's
  pixels and a medium one at ~35%. Fine detail disappears.
- The colour frames have the vanilla tier tint baked in, so the replacement is
  one full-colour layer and needs no mask layers.

## How vanilla biter sprites work (verified, not documented anywhere)

- **No tier has its own art.** All four biter tiers draw the same sheets in
  `__base__/graphics/entity/biter/`: base, `-mask1`, `-mask2` and `-shadow` per
  animation (`run`, `attack`, `die`, `decay`; decay has no shadow). A tier is just
  a scale plus two tints (`prototypes/entity/enemy-constants.lua`). mask1 is
  multiply-tinted; mask2 uses `tint_as_overlay` with alpha 0.7. Factorio doesn't
  document the exact overlay blend, so the extracted colours are approximate.
- Each sheet has a `.lua` next to it (`width`, `height`, `shift`, `line_length`,
  `filenames`, `lines_per_file`), loaded by `util.sprite_load`
  (`core/lualib/util.lua`).
- **The real column count is `slice`, not `line_length`.** The attack sheet's
  `.lua` says `line_length = 16` but the image is 11 columns, matching
  `slice = 11` in `biter-animations.lua`. Decay is the same (8 vs 7). The docs
  only say `slice` is mandatory with `filenames`. The packer writes
  `slice = line_length = columns`, a combination vanilla's run and die sheets
  prove the engine reads.
- **Frame order is direction-major and contiguous**: every frame of direction 0,
  then direction 1, filling rows left to right and spilling across files.
  Directions don't start on a new row (die is 17 frames over 8 columns).
- **`shift` is in 1x pixels; sheets are 2x.** `util.by_pixel(x, y)` = `{x/32, y/32}`,
  multiplied by the tier scale (`multiply_shift`), and the sheet is drawn at
  `scale * 0.5`. One by_pixel unit is therefore two sheet pixels at every tier.
- Corpses get `animation` (die) and `decay_animation` from
  `add_biter_die_animation()` in `biter-animations.lua`. `data.lua` replaces only
  those two fields; timings, ground patch and direction shuffle stay vanilla.
- Icons are 64px with mipmaps laid out to the right (120x64). 2.0 detects the
  mipmaps itself, so `icon` alone is enough.
- Space Age, Quality and Elevated Rails don't touch small or medium biter art.

## Testing

**In game:** `tools/lab.sh` → the lab is a separate `boxelder-lab` surface with lab
tiles and always-day lighting. You play in god mode (no character), with 5 of each
tier on vanilla AI. Without a character they mostly idle and wander, so the attack
animation only shows when they have something to hit. In the lab:
`/boxelder-spawn [small|medium|both] [count]` and `/boxelder-kill [radius]`
(`die()` plays the death and decay art).

**Headless:** `tools/check.sh` uses a temp profile (`-c` config + `--mod-directory`),
so Jon's real saves and mod list are never touched. It:

1. Runs `--dump-data --check-unused-prototype-data`, then asserts that all 8
   final animations use `__boxelder__/` sheets, so a later mod can't silently
   undo the swap.
2. Runs the lab on a headless server bound to 127.0.0.1, unlisted. It counts the
   units, kills them and counts the corpses.

Neither step decodes sprites; only the graphical client does. A bad sheet layout
still has to be caught in game. If you haven't looked in game, say so.

Gotchas found getting this working:
- `game.get_entity_by_unit_number` returns nil for units: it only finds
  prototypes flagged `get-by-unit-number`. Keep entity references instead.
- The headless server console has no `/quit` (use SIGINT) and ignores SIGTERM.
  It also treats whatever is buffered on stdin as one command, so send one short
  command per write with a pause between. It shuts down on stdin EOF, which is why
  check.sh feeds it from a FIFO held open.
- `--server-settings` needs every key, so check.sh starts from
  `data/server-settings.example.json`. `auto_pause` must be false or an empty
  server never ticks.

## Paths

- Game: `~/Library/Application Support/Steam/steamapps/common/Factorio/factorio.app`
  (binary `Contents/MacOS/factorio`; data `Contents/data/{base,core,space-age}`)
- User data: `~/Library/Application Support/factorio/` (log `factorio-current.log`)
- The mod is installed as a symlink: `…/factorio/mods/boxelder -> ~/Developer/boxelder`.
- VS Code has the Factorio Modding Toolkit extension (`justarandomgeek.factoriomod-debug`).

## Git

- `art/**/*.png` goes through Git LFS (`.gitattributes`): about 3,600 files, 200 MB.
- `graphics/` is gitignored, so run `uv run tools/pack-art.py` after a fresh clone.
- A release zip needs `info.json`, `data.lua`, `locale/`, `graphics/` and nothing
  else. `art/`, `tools/` and `scenarios/` are dev-only.
